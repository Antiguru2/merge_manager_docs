# План проекта

Этот файл содержит общий план проекта и заполняется AI-ассистентом.

Здесь фиксируются крупные этапы, функциональные блоки и технические направления проекта. План является фиксированной картой проекта: пункты не переносятся между разделами по статусам, а просто отмечаются как выполненные. Личные или операционные задачи разработчика в этот файл не добавляются: для них используйте `workspace/tasks/tasks.md`.

## Фаза 1: Базовый механизм слияния

### 1.1 Ядро merge-профилей и сервис операций
- [x] Поддержать сценарий объединения `1 -> 1` через merge-профили и стратегии для полей.
- [x] Реализовать перенос FK/M2M связей, soft-delete/hard-delete донора и аудит результата.

### 1.2 Контроль выполнения и прозрачность изменений
- [x] Добавить dry-run/preview для проверки изменений до запуска реального объединения.
- [x] Завести журнал `MergeOperation` и административный интерфейс для разбора операций.

## Фаза 2: Пользовательский контур

### 2.1 API и внешняя интеграция
- [x] Предоставить REST API для профилей, поиска сущностей, предпросмотра и запуска объединения.
- [x] Документировать сценарии использования API и точки расширения (`admin_change_url`, настройки профилей).

### 2.2 Интерфейс оператора
- [x] Реализовать одностраничный UI с пошаговым сценарием выбора записей и подтверждения слияния.
- [x] Добавить быстрый переход в Django Admin из пользовательского интерфейса.

## Фаза 3: Расширение сценариев слияния

### 3.1 Автоматический подбор кандидатов
- [ ] Исследовать и внедрить fuzzy matching для предварительного поиска дублей.
- [ ] Зафиксировать критерии качества подбора и правила ручной валидации результата.

### 3.2 Масштабирование и сопровождение операций
- [ ] Спроектировать поддержку сценариев `N -> 1` для объединения нескольких доноров.
- [ ] Оценить необходимость асинхронного выполнения, webhooks, экспорта истории и отката операций.

## Заметки

- `PLAN.md` отражает продуктовый и технический roadmap модуля на высоком уровне.
- Операционные задачи разработчика и разовые действия фиксируются в `workspace/tasks/tasks.md`.
- Пункты из бывшего roadmap в `workspace/tasks/tasks.md` перенесены сюда и разделены по фазам развития.
